# 작성 규칙

## 1. 문제 원문

문제는 학습 사이트의 스크린샷이나 복사한 텍스트로 받는다. 원문은 [sources/grade3-original.md](sources/grade3-original.md)에 그대로 보관한다.

- **문제 부분은 원문 그대로 싣는다.** 시험 문제 형식을 읽는 훈련도 학습지의 목적이기 때문이다.
  - 문장, 오타, 예제 값, 입력·출력을 고치거나 줄이지 않는다.
  - 원문에 있는 오류(예: 2세트-04 예제 설명에 다른 문제 내용이 섞인 것)도 고치지 않는다.
- 지우는 것은 복사하면서 딸려 온 흔적뿐이다. 예) 입력·출력 상자의 `Copy` 글자
- 스크린샷의 레이아웃은 따르지 않는다. 문제 설명 / 입력 설명 / 출력 설명 / 예제 / 입력·출력 / 예제 설명을 같은 틀로 배치한다.
- 원문에 섹션 이름이 없는 부분(예: 1세트 문제 맨 위의 한 줄 요약)도 그대로 문제 설명에 싣는다.

## 2. 용어 통일

원문이 아니라 **학습지가 쓰는 글**(조건, 단계, 힌트, 정답)에 적용한다.

| 쓸 말 | 쓰지 않을 말 |
| --- | --- |
| 리스트 | 배열 (문제 원문이 `arr`이어도 설명은 "리스트") |
| 원소 | 요소, 항목 |
| 인덱스 | 첨자 |
| 절댓값 | 절대값 |
| 문자열 | 스트링 |
| 출력한다 | 프린트한다 |

- "n번째"는 **1부터 세는 위치**를 뜻한다. 파이썬 인덱스와 다르면 반드시 함께 적는다.
  예) "짝수 번째(2, 4, 6번째) = 인덱스 1, 3, 5"

## 3. 코드 작성 규칙

시험 화면의 코드 형식을 그대로 따른다.

### 빈칸 채우기 유형

시험 코드 틀을 **그대로** 옮긴다. 변수 이름, 줄 순서, 들여쓰기를 바꾸지 않는다.
이 규칙은 **마지막 단계의 시험 코드 틀**에만 적용한다. 단계 정답과 A / B 문제의 코드는 5절 규칙을 따른다.
아래는 `2세트-01`(평균 점수)의 시험 틀에 빈칸을 채운 예시다.

```python
if __name__ == "__main__":
    score = list(map(int, input().split()))

    total_score = 0

    for subject in score :
        total_score = total_score + subject

    average = total_score / 3

    print("%.2f" % average)
```

- 세트마다 틀 모양이 다르다. 1세트는 감싸는 코드 없이 바로 시작하고, 2세트는 `if __name__ == "__main__":` 안에 쓴다. 문제마다 [sources/grade3.md](sources/grade3.md)의 틀을 따른다.
- 시험에서는 **입력 처리(`score = ⬜`)와 출력 형식(`print(⬜)`, `"⬜" % (...)`)도 빈칸으로 나온다.** 그래서 입력 처리와 출력 형식은 따로 연습시킨다.
- 시험 틀은 출력에 **`%` 포맷**(`"%d"`, `"%s"`, `"%.1f"`)을 주로 쓴다. 정답 코드와 해설도 `%` 포맷을 기본으로 하고, f-string은 `참고`로만 소개한다.
- 시험 코드 틀이 없는 빈칸 문제는 [problems.md](problems.md)에 `필요`로 표시하고 사용자에게 스크린샷을 요청한다. 스크린샷이 오기 전에는 그 문제를 만들지 않는다.

### 함수 작성 유형

빈 편집기에서 `input()` / `print()`로 처음부터 쓰는 형식이다. 코드 틀 없이 바로 쓴다.

```python
n1 = int(input())
n2 = int(input())
print(min(n1, n2))
```

### 공통

- 들여쓰기는 공백 4칸이다.
- **3급 수준의 기본 문법만** 쓴다. 리스트 컴프리헨션, `lambda`, 삼항 연산자, `import`는 쓰지 않는다.
  단, 힌트에서 "이렇게도 쓸 수 있다"고 소개하는 것은 괜찮다. 이때는 `참고`라고 밝힌다.
- 입력은 예제 형식과 **자료형**에 따라 쓴다. 문자열에 `int()`를 쓰면 `ValueError`가 난다.

  | 입력 모양 | 코드 | 예 |
  | --- | --- | --- |
  | 한 줄에 정수 하나 | `int(input())` | 1세트-03 `27` |
  | 한 줄에 정수 여러 개 | `list(map(int, input().split()))` | 2세트-01 `85 89 91` |
  | 한 줄에 문자열 하나 | `input()` (변환하지 않음) | 2세트-05 `QK`, 2세트-07 `Class2022!` |

- 모든 정답 코드는 **예제 입력으로 실제로 실행해서** 출력이 같은지 확인한 뒤에 싣는다.
  - 비교할 때는 **각 줄 끝의 공백과 맨 끝 줄바꿈은 무시**한다(줄마다 `rstrip()` 후 비교). 그 밖의 공백·글자는 그대로 같아야 한다.
  - 시험 틀 때문에 끝 공백이 생기는 문제는 해당 단계의 힌트에 적는다.
    예) 1세트-09는 시험 틀이 마지막에도 `print(end=" ")`를 실행하므로 실제 출력은 `I Io IoT `(끝 공백 1개)다.
    끝 공백은 화면에 보이지 않으며 틀을 고치지 않고 그대로 둔다.

## 4. 단계 작성 규칙

- **문체는 "~한다"체**로 딱딱하고 짧게 쓴다. 코딩 지시문처럼 쓴다. 예) "입력된 숫자 두 개를 `n1`, `n2`에 대입한다.", "`n1`, `n2`를 정수로 바꾼다."
- **단계 하나 = 할 일 하나.** 코드로는 1~4줄 정도다.
- 단계에는 **질문 한 줄과 답 쓰는 칸만** 둔다. 설명·예시·주의는 넣지 않고 장 끝 힌트로 보낸다.
- 무엇을 어떤 변수에 넣을지 분명히 적는다. 변수 이름은 힌트, 정답, 완성 코드까지 똑같이 쓴다.
- 힌트가 있는 단계에는 `힌트` 표시를 붙인다.
- 쓰기 칸 줄 수는 정답 코드 줄 수에 맞춘다. 완성 코드 칸은 남는 공간을 모두 채운다.

## 5. 풀이 방법이 여러 가지일 때 (A / B 문제)

- 풀이 방법이 둘 이상이면 **같은 문제를 A / B 두 문제로 나눈다.** 각 문제는 처음부터 끝까지 단계별로 푼다.
  - A: 내장 함수나 메서드를 쓰는 방법. 예) `min` / `max`, `sum`, `s.lower()`
  - B: 내장 함수 없이 반복문·조건문으로 직접 구현하는 방법
- 머리말 아래에 조건을 한 줄로 적는다. 예) A "내장 함수 min, max를 사용해 푼다." / B "문제는 A와 같다. 이번에는 min, max를 사용하지 않는다."
- B는 A 바로 뒤에 두고 원문은 다시 싣지 않는다.
- A / B와 단계 정답 코드는 **그 자체로 실행되는 완전한 코드**로 쓴다.
  - 시험 틀의 변수 이름을 이어 쓰지 않는다. 특히 시험 틀이 내장 함수 이름(`sum`, `str` 등)을 변수로 쓰는 경우,
    단계에서는 `total`, `s`, `text`처럼 겹치지 않는 이름을 쓴다.
    예) 1세트-04 틀은 `sum = 0`을 먼저 실행하므로, 같은 코드에서 `sum(arr[1::2])`를 부르면 `TypeError`가 난다.
  - 이름이 겹치면 안 되는 이유는 해당 단계의 힌트에 적는다.
- 풀이 방법이 사실상 하나뿐인 문제는 나누지 않는다.

## 6. 힌트 작성 규칙

- 장 끝 "힌트"에 문제별·단계 번호별로 싣는다.
- **문체는 "~한다"체**, 설명은 **일반적으로** 쓴다. 그 문제의 답을 그대로 쓰지 않고, 필요한 문법이 어떻게 동작하는지 설명한다.
  - 예시는 **문제와 다른 값·변수**로 든다(예: `age = int(age)`).
  - 인덱스, "번째"와 인덱스의 차이, 문자열의 글자 위치처럼 막히기 쉬운 개념은 **칸 그림**으로 보여 준다.
- 틀리기 쉬운 점도 힌트에 쓴다. 예)
  - `input()`의 결과는 문자열이다. 바꾸지 않으면 `"100" < "27"`이 `True`가 된다.
  - `arr[n]`은 n번째가 아니라 n+1번째다.
  - `round(88.0, 2)`는 `88.0`으로 출력된다. 자릿수를 고정하려면 `"%.2f" % x`를 쓴다.
  - `/`의 결과는 항상 실수다. `33 / 1`은 `33.0`이다.
  - 문자열 비교는 사전 순서다. `"yellow" > "green"`은 `True`다.
- 시험 코드가 단계와 다른 방법을 쓰면(예: 2세트-05는 `index()` 대신 반복문), 시험 틀 단계의 힌트에 동작 순서를 2~4줄로 설명한다.

## 7. 마지막 단계와 정답

- **함수 작성 문제**: 마지막 단계는 "완성 코드를 작성한다"이다.
- **빈칸 채우기 문제**: 단계별로 푼 뒤 "완성 코드를 작성한다"를 두고, **맨 마지막 단계에서 시험 코드 틀의 빈칸**을 채운다. 빈칸 번호는 ①②③ 순서다.
- **정답은 장 끝, 힌트 다음에 모은다.** 문제마다 단계 번호별 정답, 완성 코드, 시험 빈칸 정답(①②③)과 채운 전체 코드(⟦ ⟧ 강조)를 싣는다.
- 정답이 여러 가지로 가능하면 함께 적는다. 예) "1과 합쳐 `n1 = int(input())`도 정답"
