# 작업 방식

## 1. 브랜치

- `main`에는 직접 커밋하지 않는다. 모든 작업은 브랜치에서 하고 PR로 올린다.
- 브랜치 이름

| 종류 | 형식 | 예 |
| --- | --- | --- |
| 규칙 문서 | `docs/<주제>` | `docs/rules` |
| 템플릿·스타일 | `feat/<주제>` | `feat/template` |
| 학습지 내용 | `content/<급수>-<장>` | `content/g3-ch01` |
| 수정 | `fix/<주제>` | `fix/print-margin` |

## 2. PR

- **큰 기능 하나 = PR 하나.** 진행 순서는 아래와 같다.
  1. 규칙 문서 (`docs/`)
  2. 디자인 템플릿 (공통 CSS + 문제 페이지 견본)
  3. 표지 · 한 장 요약
  4. 장별 학습지 (장 하나 = PR 하나)
- PR 설명에 쓸 것
  - 무엇을 했는지
  - 원문을 고친 곳 목록 (학습지 PR)
  - 확인한 방법 (예: 정답 코드를 예제 입력으로 실행한 결과, 인쇄 미리보기 확인)
  - **미리보기 링크** (학습지·디자인 PR): `https://jxxngin.github.io/cos-pro/pr-preview/pr-<번호>/` 와 확인할 페이지 주소
- PR을 만들 때 assignee를 사용자로 지정한다.
- **머지는 사용자가 직접 한다.** Claude는 머지하지 않는다.

## 3. 검수 (미리보기 사이트)

- 학습지 검수는 **랩장님**이 브라우저로 한다. GitHub 계정 없이도 볼 수 있도록 링크로 전달한다.
- PR을 열면 GitHub Actions가 PR 미리보기를 배포하고 PR에 링크 댓글을 단다. 커밋을 추가하면 미리보기도 갱신되고, PR이 머지되거나 닫히면 지워진다.
- 머지된 버전은 `https://jxxngin.github.io/cos-pro/` 에서 볼 수 있다.
- 인쇄 모양은 브라우저 인쇄 미리보기(`Ctrl + P`)로 확인한다.

## 4. 리뷰 대응

1. 리뷰 내용이 **옳은 지적인지 먼저 검토**한다. 맞으면 고치고, 동의하지 않으면 근거를 적는다.
2. 고친 내용은 새 커밋으로 올린다. 기존 커밋을 덮어쓰지 않는다.
3. 리뷰 스레드에 **어떻게 해결했는지 답글**을 단다. 고친 커밋을 함께 적는다.
4. 답글을 단 뒤 **스레드를 resolve**한다.
5. 다음 PR은 이전 PR이 머지된 `main`에서 새로 브랜치를 만든다.
