# 작성 규칙

## 1. 원문 정리 · 검수

문제는 학습 사이트의 스크린샷이나 복사한 텍스트로 받는다.

- **스크린샷의 레이아웃은 무시하고 내용만 쓴다.**
- 복사하면서 딸려 온 내용은 지운다. 예: 입력·출력 코드 상자의 `Copy` 버튼 글자, 같은 내용이 반복되는 입력·출력 블록
- **작성자(Claude)가 직접 검수해서 고친다.** 따로 묻지 않는다.
  - 오타·맞춤법: 예) `두 번재` → `두 번째`, `절대값` → `절댓값`
  - 문제와 상관없는 내용: 예) 다른 문제의 예제 설명이 섞여 들어간 경우 → 문제에 맞게 다시 쓴다.
  - 빠진 표시: 예) `입력` 머리글이 빠진 경우
- 고친 곳에는 작은 `원문 수정` 표시를 남긴다. 단, 맞춤법·띄어쓰기처럼 뜻이 바뀌지 않는 수정에는 남기지 않는다.
- 고친 내용은 PR 설명에 목록으로 적는다.
- 문제 요약은 원문 표현을 최대한 살리되, 2~3줄로 줄인다. 입력 범위처럼 풀이에 영향을 주는 조건은 빼지 않는다.

## 2. 용어 통일

| 쓸 말 | 쓰지 않을 말 |
| --- | --- |
| 리스트 | 배열 (문제 원문이 `arr`이어도 설명은 "리스트") |
| 원소 | 요소, 항목 |
| 인덱스 | 첨자 |
| 절댓값 | 절대값 |
| 문자열 | 스트링 |
| 출력한다 | 프린트한다 |

- "n번째"는 **1부터 세는 위치**를 뜻한다. 파이썬 인덱스와 다르면 반드시 함께 적는다.
  예) "짝수 번째(2, 4, 6번째) = 인덱스 1, 3, 5"

## 3. 코드 작성 규칙

시험 화면의 코드 형식을 그대로 따른다.

### 빈칸 채우기 유형

시험 코드 틀을 **그대로** 옮긴다. 변수 이름, 줄 순서, 들여쓰기를 바꾸지 않는다.
이 규칙은 **최종 미션의 시험 코드 틀**에만 적용한다. 미션 정답과 A / B 문제의 코드는 5절 규칙을 따른다.
아래는 `2세트-01`(평균 점수)의 시험 틀에 빈칸을 채운 예시다.

```python
if __name__ == "__main__":
    score = list(map(int, input().split()))

    total_score = 0

    for subject in score :
        total_score = total_score + subject

    average = total_score / 3

    print("%.2f" % average)
```

- 세트마다 틀 모양이 다르다. 1세트는 감싸는 코드 없이 바로 시작하고, 2세트는 `if __name__ == "__main__":` 안에 쓴다. 문제마다 [sources/grade3.md](sources/grade3.md)의 틀을 따른다.
- 시험에서는 **입력 처리(`score = ⬜`)와 출력 형식(`print(⬜)`, `"⬜" % (...)`)도 빈칸으로 나온다.** 그래서 입력 처리와 출력 형식은 따로 연습시킨다.
- 시험 틀은 출력에 **`%` 포맷**(`"%d"`, `"%s"`, `"%.1f"`)을 주로 쓴다. 정답 코드와 해설도 `%` 포맷을 기본으로 하고, f-string은 `참고`로만 소개한다.
- 시험 코드 틀이 없는 빈칸 문제는 [problems.md](problems.md)에 `필요`로 표시하고 사용자에게 스크린샷을 요청한다. 스크린샷이 오기 전에는 그 문제를 만들지 않는다.

### 함수 작성 유형

빈 편집기에서 `input()` / `print()`로 처음부터 쓰는 형식이다. 코드 틀 없이 바로 쓴다.

```python
n1 = int(input())
n2 = int(input())
print(min(n1, n2))
```

### 공통

- 들여쓰기는 공백 4칸이다.
- **3급 수준의 기본 문법만** 쓴다. 리스트 컴프리헨션, `lambda`, 삼항 연산자, `import`는 쓰지 않는다.
  단, 알아 두기에서 "이렇게도 쓸 수 있다"고 소개하는 것은 괜찮다. 이때는 `참고`라고 밝힌다.
- 입력은 예제 형식과 **자료형**에 따라 쓴다. 문자열에 `int()`를 쓰면 `ValueError`가 난다.

  | 입력 모양 | 코드 | 예 |
  | --- | --- | --- |
  | 한 줄에 정수 하나 | `int(input())` | 1세트-03 `27` |
  | 한 줄에 정수 여러 개 | `list(map(int, input().split()))` | 2세트-01 `85 89 91` |
  | 한 줄에 문자열 하나 | `input()` (변환하지 않음) | 2세트-05 `QK`, 2세트-07 `Class2022!` |

- 모든 정답 코드는 **예제 입력으로 실제로 실행해서** 출력이 같은지 확인한 뒤에 싣는다.
  - 비교할 때는 **각 줄 끝의 공백과 맨 끝 줄바꿈은 무시**한다(줄마다 `rstrip()` 후 비교). 그 밖의 공백·글자는 그대로 같아야 한다.
  - 시험 틀 때문에 끝 공백이 생기는 문제는 해당 미션의 "주의"에 적는다.
    예) 1세트-09는 시험 틀이 마지막에도 `print(end=" ")`를 실행하므로 실제 출력은 `I Io IoT `(끝 공백 1개)다.
    끝 공백은 화면에 보이지 않으며 틀을 고치지 않고 그대로 둔다.

## 4. 미션 작성 규칙

이 학습지의 중심이다. 초등학생도 따라올 수 있게, 한 번에 한 가지만 시킨다.

- **미션 하나 = 할 일 하나.** 코드로는 1~4줄 정도. 두 가지를 한 번에 시키지 않는다.
- **알아 두기를 질문보다 먼저** 둔다. 그 미션에 필요한 문법을 먼저 설명하고, 짧은 예시를 보여 준다.
  - 예시는 **문제와 다른 값·변수**로 든다(예: `age = int(age)`). 예시를 그대로 베끼면 답이 되지 않게 한다.
  - 막히기 쉬운 개념(인덱스, "번째"와 인덱스의 차이, 문자열의 글자 위치 등)은 **칸 그림**으로 먼저 보여 준다.
- **질문은 한 문장**으로 짧게 쓴다. 무엇을 어떤 변수에 넣을지 분명히 적는다. 예) "첫째 줄을 `line`에 받아 보세요."
- **말투는 "~해요"체**로 쓴다. 용어가 처음 나오면 바로 풀어 쓴다. 예) "인덱스(칸 번호)", "문자열(글자)"
- 미션에 쓰는 변수 이름은 장 끝 정답과 최종 미션까지 똑같이 쓴다.
- 반복되는 미션은 장의 첫 문제에서만 자세히 설명한다. → [structure.md](structure.md) 3절

## 5. 풀이 방법이 여러 가지일 때 (A / B 문제)

- 풀이 방법이 둘 이상이면 **같은 문제를 A / B 두 문제로 나눈다.** 각 문제는 처음부터 끝까지 미션으로 푼다.
  - A: 내장 함수나 메서드를 쓰는 방법. 예) `min` / `max`, `sum`, `s.lower()`
  - B: 내장 함수 없이 반복문·조건문으로 직접 구현하는 방법
- B는 A 바로 뒤에 두고, 문제 읽기는 "문제는 A와 같아요"처럼 짧게 쓴다.
- A / B와 미션 정답 코드는 **그 자체로 실행되는 완전한 코드**로 쓴다.
  - 시험 틀의 변수 이름을 이어 쓰지 않는다. 특히 시험 틀이 내장 함수 이름(`sum`, `str` 등)을 변수로 쓰는 경우,
    미션에서는 `total`, `s`, `text`처럼 겹치지 않는 이름을 쓴다.
    예) 1세트-04 틀은 `sum = 0`을 먼저 실행하므로, 같은 코드에서 `sum(arr[1::2])`를 부르면 `TypeError`가 난다.
  - 이름이 겹치면 안 되는 이유는 해당 미션의 "주의"에 한 줄로 적는다.
- 풀이 방법이 사실상 하나뿐인 문제는 나누지 않는다.

## 6. 주의

- 미션 안에 `⚠ 주의` 한 줄로 쓴다. 미션당 0~1개.
- 실제로 틀리기 쉬운 것만 쓴다. 예)
  - `input()`의 결과는 문자열이다. 바꾸지 않으면 `"100"`이 `"27"`보다 작다고 나온다.
  - `arr[n]`은 n번째가 아니라 n+1번째다.
  - `round(88.0, 2)`는 `88.0`으로 출력된다. 자릿수를 고정하려면 `"%.2f" % x`를 쓴다.
  - `/`의 결과는 항상 실수다. `33 / 1`은 `33.0`이다.
  - 문자열 비교는 사전 순서다. `"yellow" > "green"`은 `True`다.

## 7. 최종 미션과 정답

- **함수 작성 문제**: 최종 미션은 "미션을 모아 완성 코드를 처음부터 다시 쓰기"다. 남는 공간을 쓰기 줄로 채운다.
- **빈칸 채우기 문제**: 미션으로 문제를 푼 뒤 "완성 코드 쓰기"를 하고, **마지막 미션에서 시험 코드 틀의 빈칸**을 채운다.
  - 시험 코드가 미션과 다른 방법을 쓰면(예: 2세트-05는 `index()` 대신 반복문), 알아 두기에서 동작 순서를 2~4줄로 설명한다.
  - 같은 쪽에 시험 틀의 정답 코드를 보여 주지 않는다. 빈칸 번호는 ①②③ 순서다.
- **정답은 장 끝에 모은다.** 문제마다 미션 번호별 정답, 완성 코드, 시험 빈칸 정답(①②③)과 채운 전체 코드(⟦ ⟧ 강조)를 싣는다.
- 미션 정답이 여러 가지로 가능하면 함께 적는다. 예) "미션 1과 합쳐 `n1 = int(input())`도 정답"
