# 작성 규칙

## 1. 원문 정리 · 검수

문제는 학습 사이트의 스크린샷이나 복사한 텍스트로 받는다.

- **스크린샷의 레이아웃은 무시하고 내용만 쓴다.**
- 복사하면서 딸려 온 내용은 지운다. 예: 입력·출력 코드 상자의 `Copy` 버튼 글자, 같은 내용이 반복되는 입력·출력 블록
- **작성자(Claude)가 직접 검수해서 고친다.** 따로 묻지 않는다.
  - 오타·맞춤법: 예) `두 번재` → `두 번째`, `절대값` → `절댓값`
  - 문제와 상관없는 내용: 예) 다른 문제의 예제 설명이 섞여 들어간 경우 → 문제에 맞게 다시 쓴다.
  - 빠진 표시: 예) `입력` 머리글이 빠진 경우
- 고친 곳에는 작은 `원문 수정` 표시를 남긴다. 단, 맞춤법·띄어쓰기처럼 뜻이 바뀌지 않는 수정에는 남기지 않는다.
- 고친 내용은 PR 설명에 목록으로 적는다.
- 문제 요약은 원문 표현을 최대한 살리되, 2~3줄로 줄인다. 입력 범위처럼 풀이에 영향을 주는 조건은 빼지 않는다.

## 2. 용어 통일

| 쓸 말 | 쓰지 않을 말 |
| --- | --- |
| 리스트 | 배열 (문제 원문이 `arr`이어도 설명은 "리스트") |
| 원소 | 요소, 항목 |
| 인덱스 | 첨자 |
| 절댓값 | 절대값 |
| 문자열 | 스트링 |
| 출력한다 | 프린트한다 |

- "n번째"는 **1부터 세는 위치**를 뜻한다. 파이썬 인덱스와 다르면 반드시 함께 적는다.
  예) "짝수 번째(2, 4, 6번째) = 인덱스 1, 3, 5"

## 3. 코드 작성 규칙

시험 화면의 코드 형식을 그대로 따른다.

### 빈칸 채우기 유형

시험 코드 틀을 **그대로** 옮긴다. 변수 이름, 줄 순서, 들여쓰기를 바꾸지 않는다.
아래는 `2세트-01`(평균 점수)의 시험 틀에 빈칸을 채운 예시다.

```python
if __name__ == "__main__":
    score = list(map(int, input().split()))

    total_score = 0

    for subject in score :
        total_score = total_score + subject

    average = total_score / 3

    print("%.2f" % average)
```

- 세트마다 틀 모양이 다르다. 1세트는 감싸는 코드 없이 바로 시작하고, 2세트는 `if __name__ == "__main__":` 안에 쓴다. 문제마다 [sources/grade3.md](sources/grade3.md)의 틀을 따른다.
- 시험에서는 **입력 처리(`score = ⬜`)와 출력 형식(`print(⬜)`, `"⬜" % (...)`)도 빈칸으로 나온다.** 그래서 입력 처리와 출력 형식은 따로 연습시킨다.
- 시험 틀은 출력에 **`%` 포맷**(`"%d"`, `"%s"`, `"%.1f"`)을 주로 쓴다. 정답 코드와 해설도 `%` 포맷을 기본으로 하고, f-string은 `참고`로만 소개한다.
- 시험 코드 틀이 없는 빈칸 문제는 [problems.md](problems.md)에 `필요`로 표시하고 사용자에게 스크린샷을 요청한다. 스크린샷이 오기 전에는 그 문제를 만들지 않는다.

### 함수 작성 유형

빈 편집기에서 `input()` / `print()`로 처음부터 쓰는 형식이다. 코드 틀 없이 바로 쓴다.

```python
n1 = int(input())
n2 = int(input())
print(min(n1, n2))
```

### 공통

- 들여쓰기는 공백 4칸이다.
- **3급 수준의 기본 문법만** 쓴다. 리스트 컴프리헨션, `lambda`, 삼항 연산자, `import`는 쓰지 않는다.
  단, 풀이 방법 비교에서 "이렇게도 쓸 수 있다"고 소개하는 것은 괜찮다. 이때는 `참고`로 표시한다.
- 입력은 예제 형식을 따른다. 한 줄에 하나면 `int(input())`, 한 줄에 여러 개면 `list(map(int, input().split()))`
- 모든 정답 코드는 **예제 입력으로 실제로 실행해서** 출력이 같은지 확인한 뒤에 싣는다.

## 4. 풀이 방법 비교 규칙

이 학습지의 중심이다.

- 문제마다 **방법 A / 방법 B 두 가지**를 기본으로 한다.
  - 방법 A: 내장 함수나 메서드를 쓰는 방법. 예) `sum(score)`, `s.lower()`, `arr[1::2]`
  - 방법 B: 반복문·조건문으로 직접 구현하는 방법. 예) `for`로 하나씩 더하기
- 풀이 방법이 사실상 하나뿐인 문제는 하나만 싣고, 대신 "헷갈리기 쉬운 점"을 늘린다.
- **시험 코드 틀이 쓰는 방법**에 `시험 코드 방식` 표시를 붙인다. 빈칸 채우기 문제는 시험 틀의 방식을 알아야 빈칸을 채울 수 있기 때문이다.
- 방법마다 한 줄 메모를 붙인다. 예) "가장 짧다", "빈칸 문제에 자주 나오는 형태", "인덱스 범위 실수 주의"
- 같은 장 안에서 같은 비교가 반복되면, 장 머리띠에 한 번 정리하고 문제에서는 짧게 가리킨다.

## 5. 헷갈리기 쉬운 점

- 문제당 1~3개, 반 쪽 문제는 1개.
- 실제로 틀리기 쉬운 것만 쓴다. 예)
  - `round(88.0, 2)`는 `88.0`으로 출력된다. 자릿수를 고정하려면 `"%.2f" % x`를 쓴다.
  - `/`의 결과는 항상 실수다. `33 / 1`은 `33.0`이다.
  - 문자열 비교는 사전 순서다. `"yellow" > "green"`은 `True`다.
  - `input()`의 결과는 문자열이다. 숫자로 계산하려면 `int()`로 바꿔야 한다.

## 6. 직접 써 보기 규칙

- 정답 코드에서 **이 문제의 핵심 줄**을 빈칸으로 만든다. 빈칸 번호는 ①②③ 순서다.
- 빈칸 채우기 유형은 시험과 같은 위치를 빈칸으로 만들고, 여기에 핵심 줄을 하나 더 뺄 수 있다.
- 함수 작성 유형은 코드 전체를 쓸 수 있도록 **빈 줄 공간**을 준다(1쪽 문제 6~8줄, 반 쪽 문제 3~4줄).
- 정답은 장 끝 정답 쪽에 문제 번호와 함께 싣는다.
